# Phase 4A — local BiRefNet Lite cutout

Selected experimental model: https://huggingface.co/clevr-tools/birefnet-lite-web (MIT, original BiRefNet by Peng Zheng et al., arXiv:2401.03407). 512 WASM export: 101066931 bytes, SHA-256 20e3fb3e7bbb75e0b4f152759413a6ab19a599a1c2e1db7ce7741792eaf639fb. The model card describes ImageNet normalization, input_image [1,3,512,512] and output_image logits [1,1,512,512]. Runtime candidate: onnxruntime-web 1.23.2, separately installed and reviewed, MIT. No runtime package or model is included in the app lockfile or shipped by this commit.

Local proof only: after review, use an isolated temporary directory to npm pack onnxruntime-web@1.23.2, extract the archive, copy package/dist/ort.wasm.min.mjs and matching ort-wasm-simd-threaded.mjs/.wasm assets to public/studio-local/assets (verify actual package filenames and licensing before use). Download birefnet_lite_512_fp16w.onnx from the above model repo, verify exact size/hash and place it in the same assets directory; retain upstream LICENSE and NOTICE and runtime license. The worker re-verifies the model before inference. Never download executable JS at runtime from an unpinned CDN. Do not deploy local assets with production web builds; hosting of >100 MB assets needs a separate verified free strategy. Assets are gitignored. No install or download has been performed here.

Worker uses WASM in a separate thread, reuses a session during an editor lifetime, uses no image network upload, and returns a transparent PNG limited to 1600 pixels per side. Only the alpha channel is multiplied by the predicted soft matte; original source is retained. Ambiguous/degenerate masks fail closed. Cancel/timeout terminates worker; manual original-photo fallback remains the intended UX. Browser compatibility, memory, runtime files, actual model inference and quality on metal parts (holes, reflective surfaces, thin edges) remain unverified. Local-only test gate before user-facing enablement; model may be slow on CPU. Real model files are not required for automated unit tests, which use synthetic tensors and mocked workers. No UI or production changes.
