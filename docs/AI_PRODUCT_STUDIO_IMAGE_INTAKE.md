# Phase 2B-2 — restricted PNG intake

The server-side studio decoder accepts only bounded static 8-bit RGB/RGBA non-interlaced PNG: max 1024 pixels per side, 5 MiB input, 256 chunks. It validates signature, CRC, chunk ordering, dimensions, bounded zlib decompression, exact filtered scanline lengths and filter identifiers. It then recompresses the filtered pixel stream and reconstructs a PNG from IHDR/IDAT/IEND only. Ancillary metadata is discarded. Color profile metadata is intentionally discarded; the future browser must normalize to sRGB when preparing the photo. No generative changes to pixels are intended. This is a deliberately restricted PNG sanitizer, not a general-purpose decoder or full PNG conformance validator.

Design references: https://www.w3.org/TR/png/ and https://developers.cloudflare.com/workers/runtime-apis/web-standards/. No dependencies or paid image API. Browser preparation (not yet implemented) will accept JPEG/PNG/WebP, decode locally, resize to 1024 max side, and export static RGB/RGBA PNG; original product photos remain untouched. Only a downscaled analysis copy is intended for Gemini.

Tests use real compressed RGB/RGBA scanlines generated independently with node:zlib, plus malformed, oversized and metadata fixtures. Before deployment, test real browser Canvas PNG outputs, runtime CPU/memory on the Cloudflare Free plan, and malformed/fuzz samples. Actual HTTP route, streaming request body cap, authenticated admin, quota transaction emulator test, provider smoke test and client UI remain separate gates. No endpoint, deployment, secrets, production changes or live AI request in this commit.
