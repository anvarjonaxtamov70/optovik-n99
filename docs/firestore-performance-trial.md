# Candidate performance trial (synthetic only)
Deploy only the candidate Worker after CI and operator approval. Do not change production, RTDB, credentials or dataset guard.
Baseline and after: use browser Network tab, record POST /v1/transition total duration and Server-Timing (auth, runner, firestore, total). Expo development console logs token acquisition and HTTP duration without IDs or payloads. Old deployment has no Server-Timing; use HTTP duration and record it as baseline. Record button-to-status time separately. Use same device/network, at least 5 confirm/cancel pairs, fresh synthetic orders (respect rate limits), compare median and slowest; verify stock before/after each and repeat requests do not change stock twice. Do not use customer data. A lost response must be reconciled by read, not automatic mutation retry. Local events refresh same-app views; other devices remain on bounded polling. No new service or shorter polling interval. Timing is not a live performance claim.
